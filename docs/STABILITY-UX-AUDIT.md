# 工作站稳定性与体验审计

更新时间：2026-08-09

## 已在本轮修复

- 页面级错误边界：单个模块渲染失败时保留导航和恢复入口，不再整站白屏。
- 应用级错误边界：启动阶段异常会显示可读的恢复页面。
- 创作入口数据清洗：损坏或不安全的网址不会再通过 `new URL()` 让创作发布页崩溃。
- 任务数据清洗：旧版本或备份中的异常任务会在读取时跳过，而不是污染全部页面。
- AI 多轮对话：前端显示连续消息流，后端接收最近 12 条经过限制的历史消息。
- DeepSeek V4：普通工作站请求显式使用非思考模式，避免短输出只返回思考内容。

## 下一阶段优先级

### P0：稳定性

1. 把 `App.tsx` 中七个页面拆成独立模块，页面只接收必要的数据和动作。
2. 为 Canvas、需求实验和产品蓝图增加更严格的本地存储结构校验。
3. 为所有本机 API 增加统一的错误结构、超时提示和重试动作。
4. 增加浏览器端冒烟测试，至少覆盖七个导航页面、弹窗打开/关闭和空数据状态。

### P1：交互一致性

1. 统一页面标题高度、主操作位置、空状态和错误提示。
2. 将设置拆成“知识库、AI 模型、数据备份”三个清晰区域。
3. 给耗时操作增加骨架屏或局部加载状态，避免按钮点击后像卡死。
4. 统一删除、清空、覆盖等危险操作的确认方式。

### P2：视觉优化

1. 减少同质化白色描边卡片，用分组、留白和底色表达层级。
2. 收紧超宽屏内容密度，数据页和任务页使用更适合工作台的栅格。
3. 统一数字、标签、辅助文字和状态色，避免每个模块各自形成一套视觉语言。
4. 为 AI、知识库和无限画布建立更明显的工作区形态，而不是普通表单堆叠。

## 验收标准

- 任一页面内部异常不会让导航消失或显示纯白页面。
- 损坏的浏览器缓存不会阻止应用启动。
- AI 能连续追问，并能在消息中展示使用的知识库来源。
- 七个导航页面都有加载、空数据、错误和可恢复状态。
- 生产构建通过，并有自动化冒烟测试覆盖核心路径。
