# 小黄的创作者工作站

这是一个用来澄清和验证个人工作流的本地可交互原型。当前围绕六个已经确认的核心板块组织，不把尚未确定的需求提前做成复杂系统。

## 已实现

- 工作台：汇总今日任务、常用创作入口、完成情况、快速捕获与 Vault 状态；首次设置只保留连接知识库、添加真实任务和验证模型三步。
- 目标任务：添加“今日任务”或“最近目标”，记录创建与完成时间，并保存在浏览器本地；首次新增会替换演示任务。
- 可选任务同步：用户主动启用后，将目标任务保存到当前 Vault 的工作站管理区；已有 `_系统` 时使用 `_系统/工作站/任务.md`，否则使用 `Workstation/Tasks.md`。版本指纹会阻止覆盖 Obsidian 中的新修改。
- 创作发布：预置常见创作者后台直达链接，也可添加自己的 HTTPS 地址；前 3 项会显示在首页，并可上下调整顺序。
- 每日复盘与数据：工作站记录任务新建、完成、重开、删除、恢复和知识捕获等真实操作；每天结束时用三个问题补充自己的判断，生成 Markdown 并安全保存到 `Workstation/Reviews/YYYY-MM-DD.md`（存在 `_系统` 时保存到 `_系统/工作站/复盘`）。同名文件若不是工作站创建的内容会拒绝覆盖，已保存文件也带版本冲突保护。
- 私人知识库：Obsidian 保存用户长期积累的 Markdown；工作站提供只读搜索、打开原文和受控捕获，但不把任务、日历或平台数据强行改造成 Obsidian 数据。
- 无限画布：自由摆放便签、任务、知识卡和本机附件；支持图片、视频、音频、PDF、文本的选择、拖入和粘贴预览，一个卡片可连接多条关系线。卡片可拖动右下角自由缩放，也可快速切换紧凑、标准、宽幅尺寸；自动整理会按真实卡片尺寸留出空间。可从三种实验模板开始，并通过画布 AI 先预览再加入节点。画布稳定保存在桌面应用的数据目录，也可导入或导出 `.canvas` 文件；Obsidian 的附件节点目前按路径互通，不会把附件文件本身打包进 `.canvas`。
- AI 私人管家：支持用户配置自己的 DeepSeek、Kimi、智谱 GLM、通义千问、豆包火山方舟或自定义兼容 API；知识问答先在本机按问题检索 Vault，只把最多 8 个相关片段发给模型，答案保留笔记来源。没有命中时不会让模型假装从知识库得出答案。
- 知识检索校准：无需模型 API 即可用真实问题测试当前 Vault，评价命中是否准确、是否遗漏或不相关；评价只存在当前浏览器，并根据累计结果提示是否值得增加本机向量索引。
- 快速捕获：先预览 Markdown，再确认追加到连接器为当前 Vault 选择的独立捕获文件；最近捕获可以转为今日任务或归档，处理后不再计入待整理数量。已有 `00_收件箱` 时会使用 `00_收件箱/工作站捕获.md`，否则默认使用 `Inbox/Capture.md`。

## Windows 桌面应用

项目已经接入 Electron，可作为独立 Windows 应用运行，不需要保留浏览器标签页。

- 当前交付版本：`0.6.0`（Apple/macOS 风格界面、明暗主题、稳定的可缩放画布与完整视觉回归）。
- 从源码构建需要 Node.js 22.12 或更高版本。
- 开发模式：`npm run desktop:dev`
- 生成免安装目录：`npm run desktop:pack`
- 生成 Windows 安装包：`npm run desktop:dist`

桌面版使用固定的本机地址和独立的 Windows 用户数据目录，完全退出后再次打开不会因为端口变化而看似丢失任务或画布。API Key、Vault 路径和桌面版状态不会写进交付压缩包；首次使用需要在桌面版中连接 Vault 并配置模型。当前版本没有购买代码签名证书，Windows 可能显示“未知发布者”。

## Demo Vault

未配置真实路径时，工作站使用仓库内的 `demo-vault`。默认写入严格限定为：

```text
demo-vault/Inbox/Capture.md
```

只有主动启用任务同步后，才会创建并管理：

```text
demo-vault/Workstation/Tasks.md
```

知识库连接器会只读扫描 Markdown，跳过隐藏目录，限制为最多 500 篇、单篇不超过 1 MB、目录深度不超过 8 层。首版使用本机关键词与中文片段相关性检索，不需要向量数据库；检索预览不会调用外部模型。

## 连接真实 Obsidian Vault

启动工作站后，点击右上角“连接 Obsidian”，粘贴 Vault 的完整文件夹路径。连接器会验证目录、识别已有的 `00_收件箱` 或 `Inbox`，并把路径与捕获文件落点保存在仅限本机的 `.workstation.local.json` 中；该文件已加入 `.gitignore`。查看连接状态、列出笔记和知识检索均为只读，不会为了检查状态创建目录或文件。

也可以在启动前通过环境变量指定路径。环境变量的优先级高于界面配置：

```powershell
$env:WORKSTATION_VAULT_PATH='D:\你的Vault路径'
npm run dev
```

快速捕获只允许操作当前连接配置记录的捕获文件；连接现有中文 Vault 时优先使用 `00_收件箱/工作站捕获.md`。任务同步与每日复盘使用带专用标记的托管文件；如果目标已存在但没有管理标记，连接器会拒绝覆盖。搜索与连接状态为只读，不会删除、创建或批量改写其他笔记。

## 配置自己的 AI 模型

模型配置页提供 DeepSeek、Kimi、智谱 GLM、通义千问和豆包火山方舟预设，并标明适用场景、还需要从控制台复制的字段以及官方申请/接入入口。DeepSeek、Kimi、智谱和豆包带有可直接修改的预填地址与模型；通义百炼按当前官方流程要求使用创建 Key 时返回的带 Workspace ID 的 API Host，因此不会预填旧的通用地址。

用户可以选择“仅保存”（不调用模型）或“保存并测试”（发送一句最小测试文本，可能产生少量 Token 费用）。

## 备份本机状态

设置中的“本机数据备份”可导出和恢复任务、创作入口、无限画布、AI 对话、界面状态、活动时间线、每日复盘草稿与检索校准。备份采用带版本号的 JSON 格式、结构校验和固定字段白名单，不包含模型 API Key、Vault 路径、画布附件文件或 Obsidian 笔记正文；恢复前会展示备份时间和数据类别数量，并要求再次确认。

进入 `/#ai` 后点击“配置模型”，选择国内模型服务，填写基础地址、模型 ID 和自己申请的 API Key。首版使用兼容 Chat Completions 的非流式接口，因此也能连接其他兼容服务或运行在 `localhost` 的本机模型。

- API Key 由本机服务读取，不进入前端代码或 `localStorage`，状态接口只返回末四位提示。
- 桌面版会使用 Windows 的安全存储能力加密 API Key；浏览器开发模式才会写入已被 `.gitignore` 排除的 `.workstation.secrets.json`。
- 不要共享用户数据目录或开发模式的密钥文件；公用电脑上使用后应点击“清除配置”。
- 云端调用前可分别选择任务、私人知识库和收件箱原文。勾选私人知识库时，完整 Vault 仍留在本机，只有针对当前问题命中的少量片段、标题和路径进入请求。
- 知识问答会在回答下显示命中片段及 Obsidian 原文入口；如果本机没有找到相关内容，系统直接说明依据不足并跳过模型调用。
- “测试连接”也会向供应商发出一次很小的请求，可能产生少量 Token 费用。

供应商的模型 ID 和地域地址可能变化，界面中的值只是可编辑预设，应以各自控制台显示为准。
