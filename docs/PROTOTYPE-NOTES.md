# 创作者工作站原型说明

## 用户已经确认的范围

1. 目标任务：查看每日任务和最近目标。
2. 创作者后台直达：快速进入内容发布与管理后台。
3. 数据仪表盘：看见完成、未完成和知识捕获情况。
4. 私人知识库：搜索 Obsidian Markdown，并保留受控写入入口；它不替代任务、日历或平台数据源。
5. AI 私人管家：先在本机从知识库检索与问题相关的片段，只把最少上下文交给用户配置的模型，并在答案中保留来源。
6. 无限画布：先提供便签、任务、知识卡和连线，不预设最终要替代哪一种工具。

知识问答页面同时提供一个不调用模型的校准区：用真实问题检查命中笔记，评价“准确、有用但不完整、不相关”，并把评价留在浏览器本机。连续真实问题的评价结果用于决定是否需要向量索引，而不是因为“AI 知识库”这个名称就提前增加复杂基础设施。

其余模块暂不加入主导航，等真实使用后再判断。画布目前是独立实验区，不是新的任务或知识权威来源。

## 原型要回答的问题

1. 首页能否在十秒内说明今天最值得推进什么？
2. 快速捕获是否比打开笔记、寻找目录、选择模板更轻？
3. AI 或工作台写入长期资料前，目标文件和差异是否足够清楚？
4. 即使工作台停止运行，已经确认的内容是否仍是普通 Markdown？

## 当前真实能力

- React + Fluent 2 工作台可在桌面和手机宽度下运行。
- 导航、任务新增与勾选、创作链接配置、主题切换、回顾草稿和上下文选择是实际交互。
- Vite 本地接口会检查允许路径，并把确认后的捕获追加到连接配置记录的独立文件；已有中文收件箱时使用 `00_收件箱/工作站捕获.md`。
- 知识库页面会只读搜索 Vault 中的 Markdown，并重新读取捕获记录。
- 任务默认留在浏览器；用户主动启用后，同步到连接器为当前 Vault 选择的工作站管理区，并受版本检查保护。
- 无限画布会在浏览器本地保存节点、连线和视口，可导入、导出标准 `.canvas` 文件；任务与知识卡按需复制进画布，不反向修改来源。
- 画布提供选题决策、内容项目流和项目拆解三种实验模板；再次应用模板只追加到现有画布右侧，不会清空用户已经摆放的内容。
- 首页首次设置引导会区分 Demo/真实 Vault、示例/真实任务、检索是否经过评价，以及模型是仅保存还是已测试，并始终给出当前下一步。
- 首页需求实验会自动保存七个问题的本机草稿；每条回答经过预览确认后，以追加方式写入当前 Vault 的工作站管理区。
- 工作站蓝图把需求证据转成模块去留、判断依据与下一步实验；草稿留在本机，确认后保存到当前 Vault 的工作站管理区并受版本冲突保护。
- Demo Vault 可以在界面中通过本地路径切换为真实 Vault，也可由环境变量指定。

## 当前假设或占位

- 初始任务是明确标注的示例，不计入仪表盘；新增第一项真实任务时会自动移除示例。
- 创作者平台入口是可编辑的预置项，尚未按用户真实使用频率排序。
- AI 模型由用户自行配置，首批提供五个国内服务和自定义兼容接口；未配置时只生成本地结构化草稿，不伪造模型回答。云端调用只发送用户当次明确勾选的上下文。
- 数据仪表和复盘草稿只使用本地任务与捕获，还没有接入各创作平台的真实指标。
- 真实 Vault 的目录、模板、YAML 字段、同步方式和插件尚未确认。
- 是否长期把 Obsidian 作为任务权威来源，仍需用真实工作日验证；当前实现保持可选。
- 首版知识问答使用本机关键词与中文片段相关性检索；连接真实 Vault 后，需要用用户自己的表达验证召回质量，再决定是否增加本机向量索引。
- 校准评价当前只保存在本机，不写入 Vault。等真实使用证明这些评价值得长期保留后，再决定是否提供明确预览的导出或写入入口。
- 画布未来最值得长期连接选题、内容流程、项目拆解还是知识关系仍未确认；当前模板只用于收集真实使用证据，不代表已经决定长期方向。

## 已验证的端到端切片

- 首次设置状态模型已覆盖 0/4、3/4 和 4/4 三种状态；模型已保存但尚未测试时不会被误判为完成。
- 知识检索回归覆盖中文自然问句、无命中跳过模型、只发送命中片段，以及忽略前端传入的整篇笔记摘要。

测试请求通过本地接口写入以下内容：

```markdown
- [ ] 自动验证：工作台已走通写入预览到 Markdown 的闭环
```

接口随后重新读取同一文件并返回该记录。权威证据保存在 `demo-vault/Inbox/Capture.md`。
